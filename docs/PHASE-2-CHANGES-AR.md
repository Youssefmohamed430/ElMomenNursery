# شرح تغييرات المرحلة الثانية — واجهة الاستخدام والهوية البصرية

هذا المستند يشرح بالتفصيل ما أُضيف في **Phase 2 — UI shell and brand system** لنظام إدارة حضانة المؤمن.

> هذه المرحلة أنشأت القشرة البصرية والتنقل ومكوّنات الواجهة القابلة لإعادة الاستخدام. صفحات الأقسام الحالية نماذج شكلية، ولم تُربط بعد بقاعدة بيانات أو بحالات استخدام فعلية.

## 1. مكان العمل ونطاق التغييرات

تم تنفيذ التغييرات على المشروع الموجود في:

```text
E:\Projects\Elmomen Desktop App\ElMomenNursery
```

بقيت التقنية كما هي: واجهة Windows Forms ومشاريع الواجهة والـ Backend ضمن Solution واحدة. لم تتم إضافة خادم أو اتصال بالإنترنت أو قاعدة بيانات مركزية، ولم تتم إضافة صفحة تقارير أو صفحة لإدارة الفروع.

## 2. استبدال نموذج البداية

أزيلت ملفات النموذج الافتراضي الفارغ `Form1`، وأصبحت نقطة التشغيل تعرض `Forms/MainForm.cs`:

- `Program.cs` ينشئ `MainForm` بعد تهيئة Windows Forms.
- `MainForm` يحدد عنوان التطبيق، واتجاه RTL، وحجمًا ابتدائيًا مناسبًا، وحدًا أدنى لحجم النافذة.
- أُنشئ تخطيط عام يتكون من شريط هوية علوي، وقائمة تنقل جانبية، ومنطقة محتوى تتغير عند اختيار القسم.
- تُزال الصفحة السابقة وتُتلف عند الانتقال لتجنب ترك عناصر واجهة غير مستخدمة في الذاكرة.

هذا التغيير يزيل النموذج التجريبي الافتراضي ويضع نقطة واضحة لبناء الشاشات القادمة.

## 3. شريط الهوية والشعار

يظهر في أعلى النافذة:

- الشعار الفعلي لحضانة المؤمن.
- اسم النظام: «نظام إدارة حضانة المؤمن».
- عبارة تعريفية قصيرة: «إدارة يومية واضحة وسهلة».

يُقرأ ملف الشعار من موارد المشروع، ويُنسخ إلى مجلد تشغيل التطبيق بإعداد في ملف المشروع. إذا لم يوجد الملف وقت التشغيل، تبقى الواجهة قادرة على عرض اسم النظام دون أن تتعطل.

مسار الشعار:

```text
ElMomenNursery\Resources\Branding\AlMoumenNurseryLogo.jpeg
```

## 4. لوحة الألوان

جُمعت الألوان من صورة الشعار، ثم اشتُقت منها درجات مناسبة للاستخدام داخل واجهة البرامج:

| الاستخدام | اللون |
|---|---|
| الأخضر الظاهر في الشعار | `#80B040` |
| الأحمر الظاهر في الشعار | `#E00000` |
| الأزرق الظاهر في الشعار | `#0040E0` |
| الأخضر الداكن للأزرار والنصوص الأساسية | `#376927` |
| خلفية الواجهة | `#F7F9F5` |
| حدود العناصر | `#DEE6DA` |

الدرجات الزاهية المأخوذة مباشرة من الشعار تستخدم كلمسات بصرية أو لحالات الرسائل، بينما يستخدم الأخضر الداكن في الإجراء الأساسي والنص على الخلفية البيضاء. نسبة تباين الأخضر الداكن مع الأبيض المحسوبة تقارب `6.54:1`. هذا فحص لوني حسابي، وليس بديلًا عن مراجعة الواجهة على شاشة الجهاز الفعلية.

توجد الألوان في مكان مركزي واحد:

```text
ElMomenNursery\Styling\BrandPalette.cs
```

## 5. القائمة الرئيسية والصفحة الرئيسية

تحتوي القائمة الجانبية حاليًا على:

- الرئيسية
- الأطفال
- الموظفون
- الفصول
- الحضور
- الاشتراكات والمدفوعات
- المخزن

ويظهر في الصفحة الرئيسية عنوان ترحيبي، واختصارات قابلة للنقر للأقسام اليومية. اختيار قسم يفتح صفحته الشكلية ويظهر حالة فارغة واضحة.

لا تحتوي الواجهة على لوحة مؤشرات أو مركز تقارير. لم أُظهر رابط الإعدادات بعد، لأن صفحة إدارة الصلاحيات يجب أن تكون للمشرف فقط، بينما تسجيل الدخول وربط القائمة بصلاحيات الحساب سيُنفذان في مرحلة الحسابات والصلاحيات.

## 6. مكوّنات واجهة قابلة لإعادة الاستخدام

أُضيفت المكوّنات التالية تحت `ElMomenNursery/Controls/`:

| الملف | الغرض |
|---|---|
| `NavigationButton.cs` | زر تنقل بنمط موحد وحالة واضحة للقسم المحدد |
| `FeedbackBanner.cs` | رسالة معلومات أو نجاح أو تنبيه أو خطأ بنص عربي واضح |
| `EmptyStatePanel.cs` | عرض حالة فارغة وعنوان ورسالة إرشادية |
| `LoadingIndicator.cs` | مؤشر تحميل مع نص للمستخدم |
| `FieldValidationHint.cs` | سطر لإظهار ملاحظة تحقق أسفل الحقل عند الحاجة |
| `FormSection.cs` | حاوية موحدة لتجميع حقول النموذج تحت عنوان |
| `FormFieldRow.cs` | صف RTL يربط عنوان الحقل بعنصر إدخال يمرره النموذج |
| `AppDialog.cs` | نافذة عربية للمعلومات والتأكيد مع زري «تأكيد» و«إلغاء» عند الحاجة |

هذه المكوّنات بنية جاهزة لإعادة الاستخدام؛ لم تُربط بعد بنماذج إدخال البيانات أو قواعد العمل.

## 7. الخط وRTL وإمكانية الاستخدام

- اختير خط `Segoe UI` كنقطة بداية لدعم العربية على Windows.
- ضُبط اتجاه النماذج والعناصر إلى اليمين، مع محاذاة النصوص والأزرار بما يناسب العربية.
- أحجام النقر الأساسية كبيرة نسبيًا: أزرار القائمة بارتفاع 50 نقطة، واختصارات الصفحة الرئيسية بحجم يسمح بقراءة العنوان والوصف.
- أُضيفت أسماء ووصف وصول للأزرار حيث يلزم، وأضيفت أدوار وصول لحالات الرسائل والتحميل.
- حالة القسم المحدد لا تعتمد على اللون وحده؛ يبقى اسم القسم ظاهرًا كنص.

لم يتمكن التنفيذ من التحقق بصريًا من تشكيل العربية أو ترتيب التنقل بلوحة المفاتيح على الجهاز النهائي بعد، لذلك تبقى هذه مراجعة مطلوبة قبل إغلاق المرحلة.

## 8. نوافذ الأقسام الحالية

النقر على قسم يفتح صفحة بسيطة تحمل اسم القسم ورسالة حالة فارغة. هذا مقصود في هذه المرحلة لتثبيت نمط العرض والتنقل قبل إضافة الوظائف.

الصفحات لا تنفذ حاليًا:

- إضافة أو تعديل الأطفال أو الموظفين.
- إدارة الفصول أو الحضور.
- تسجيل المدفوعات أو إصدار الفواتير.
- إدارة المخزن أو التصدير والطباعة.
- تسجيل الدخول أو تطبيق الصلاحيات.

## 9. ملفات المشروع التي تغيرت

أهم الملفات المضافة أو المعدلة:

- `ElMomenNursery/Program.cs` — تشغيل `MainForm`.
- `ElMomenNursery/Forms/MainForm.cs` — القشرة الرئيسية والتنقل والصفحة الرئيسية.
- `ElMomenNursery/Controls/` — عناصر الواجهة المشتركة الموضحة في الجدول.
- `ElMomenNursery/Styling/BrandPalette.cs` — الألوان والخطوط اللونية.
- `ElMomenNursery/Resources/Branding/AlMoumenNurseryLogo.jpeg` — الشعار المستخدم.
- `ElMomenNursery/ElMomenNursery.csproj` — نسخ ملف الشعار إلى مجلد التشغيل.
- `docs/ARCHITECTURE.md` — توثيق القشرة والهوية وحدودها الحالية.
- `docs/IMPLEMENTATION-ROADMAP.md` — تحديث حالة مهام Phase 2 والمهام المتبقية.

أزيلت ملفات نموذج البداية الفارغ `Form1.cs` و`Form1.Designer.cs` و`Form1.resx` بعد استبدالها بنقطة تشغيل النموذج الجديد.

## 10. ما تم التحقق منه وما لم يتم

تم التحقق من:

- وجود المشاريع الأربعة في الـ Solution.
- سلامة قراءة إعدادات المشروع المشتركة وملف مشروع الواجهة بصيغة XML.
- وجود الشعار في مسار الموارد.
- خلو قائمة التنقل الحالية من «التقارير» و«الفروع» و«الإعدادات».

عند إعداد الواجهة كان المشروع يستهدف .NET 10 ولم يكن Visual Studio 2022 17.14 قادرًا على فتحه. بناءً على طلب المستخدم أُعيد استهداف الحل إلى .NET 9، ثم نجح `dotnet build ElMomenNursery.sln` باستخدام SDK 9.0.306 دون أخطاء أو تحذيرات. لم يتم تشغيل النافذة لمراجعة شكل RTL على الشاشة، ولم تُشغّل اختبارات.

## 11. المتبقي لإغلاق Phase 2

1. تشغيل التطبيق بالاستهداف الحالي .NET 9 ومراجعته على شاشة Windows المستهدفة.
2. معاينة الواجهة على حجم شاشة الجهاز المستهدف ومراجعة تموضع القائمة RTL.
3. فحص تشكيل الحروف العربية، والأرقام، والتواريخ، والنصوص المختلطة عربي/إنجليزي.
4. مراجعة ترتيب التركيز والتنقل باستخدام لوحة المفاتيح والتباين على الشاشة والطباعة.
5. اختيار مجموعة أيقونات مناسبة بعد تحديد إصدارات Windows المدعومة؛ تستخدم القائمة حاليًا عناوين نصية واضحة.
6. ربط ظهور عناصر التنقل بصلاحيات الحساب بعد تنفيذ تسجيل الدخول والصلاحيات في Phase 4.

## الخلاصة

أصبحت هناك واجهة بداية فعلية بهوية حضانة المؤمن، وتنقل عربي RTL، واختصارات يومية، ومكوّنات مشتركة للرسائل والحالات الفارغة والتحقق والتحميل والنماذج والتأكيد. ما زالت صفحات الأقسام شكلية، وإغلاق المرحلة بالكامل يتطلب تشغيل التطبيق على SDK 9 ومراجعة الواجهة على جهاز Windows المستهدف.
