# شرح تغييرات المرحلة الأولى — تأسيس الحل وبيئة التطوير

هذا المستند يشرح بالتفصيل التغييرات التأسيسية المنفذة في **Phase 1 — Solution and developer foundation** لمشروع نظام إدارة حضانة المؤمن.

> هذه المرحلة جهزت بنية الحل وقواعد التطوير فقط. لم تتم إضافة وظائف تشغيلية للأطفال أو الموظفين أو الحضور أو المدفوعات.

## 1. مكان العمل ونطاق التعديل

تم تطبيق التغييرات على المشروع الموجود في:

```text
E:\Projects\Elmomen Desktop App\ElMomenNursery
```

الـ Solution تحتوي على مشروع واجهة Windows Forms وثلاثة مشاريع Backend ضمن نفس الحل. لم تتم إضافة خادم أو قاعدة بيانات مركزية أو مزامنة بين الفروع.

## 2. مشاريع الـ Solution واتجاه الاعتماد

تتكون الـ Solution من أربعة مشاريع:

| المشروع | مسؤوليته |
|---|---|
| `ElMomenNursery` | واجهة Windows Forms ونقطة تشغيل التطبيق |
| `ElMomenNursery.Application` | حالات الاستخدام والعقود التي تحتاجها الواجهة والطبقات الخارجية |
| `ElMomenNursery.Domain` | مفاهيم وقواعد العمل، من دون اعتماد على الواجهة أو مزود قاعدة بيانات |
| `ElMomenNursery.Infrastructure` | تطبيق التفاصيل الخارجية مثل التخزين المحلي والطباعة والتصدير وتكامل الأجهزة عند تنفيذها |

اتجاه الاعتماد المعتمد:

```text
واجهة Windows Forms ──> Application ──> Domain
          │
          └──────────> Infrastructure ──> Application وDomain
```

تستدعي الواجهة حالات الاستخدام من `Application`. ويجوز لها الاعتماد على `Infrastructure` عند نقطة تركيب التطبيق وتشغيله لربط التطبيقات الفعلية بالعقود. تظل `Domain` مستقلة عن باقي المشاريع. يجب ألا توضع استعلامات قاعدة البيانات أو قواعد العمل داخل أحداث النماذج.

## 3. استهداف .NET وقواعد البناء المشتركة

كان الاختيار الأول في Phase 1 هو .NET 10، لكن بعد ظهور رسالة عدم توافق Visual Studio وطلب الرجوع إلى الإصدار المتوافق مع بيئة التطوير، أصبحت الاستهدافات الحالية:

- مشروع الواجهة يستهدف `net9.0-windows` لأنه تطبيق Windows Forms.
- مشاريع `Application` و`Domain` و`Infrastructure` تستهدف `net9.0`.
- الإصدار الحالي يطابق Visual Studio 2022 17.14 و.NET SDK 9.0.306 المثبتين على الجهاز.
- انتهى دعم .NET 9 في 10 نوفمبر 2026؛ هذا اختيار للتوافق مع البيئة الحالية، وينبغي تحديث Visual Studio وإطار العمل معًا لاحقًا.

### ملف `Directory.Build.props`

أُضيفت إعدادات مشتركة للمشاريع بدل تكرارها في كل ملف مشروع:

- تفعيل Nullable Reference Types للمساعدة في اكتشاف التعامل المحتمل مع القيم الفارغة.
- تفعيل Implicit Usings لتقليل الاستيرادات المتكررة.
- تفعيل بناء حتمي قدر الإمكان عبر `Deterministic`.
- استخدام مستوى التحليل `latest`.
- تحديد Target Framework تلقائيًا حسب اسم المشروع: مشروع الواجهة يأخذ `net9.0-windows` وباقي المشاريع تأخذ `net9.0`.

أزيلت إعدادات Target Framework وNullable وImplicit Usings المكررة من ملفات المشاريع كي يكون مصدر الإعدادات مشتركًا وواضحًا.

## 4. قواعد التنسيق — `.editorconfig`

أُضيف ملف `.editorconfig` لتوحيد تنسيق الملفات عند فتح الحل في أدوات التطوير:

- ترميز UTF-8 ونهاية سطر موحدة.
- مسافات بادئة من أربع مسافات لملفات C#.
- مسافتان لملفات المشاريع وإعدادات MSBuild والحل.
- إزالة المسافات الزائدة في نهايات الأسطر.
- إضافة سطر نهائي للملفات.

الهدف هو تقليل اختلاف تنسيق الملفات بين المطورين، لا فرض أسلوب واجهة أو قواعد عمل.

## 5. قواعد استبعاد الملفات — `.gitignore`

أُضيف `.gitignore` لاستبعاد الملفات التي لا ينبغي عادةً حفظها ضمن ملفات المشروع المشتركة، ومنها:

- ملفات Visual Studio وملفات البناء الناتجة مثل `bin` و`obj`.
- إعدادات المستخدم المحلية مثل ملفات `.user` و`.suo`.
- قواعد البيانات والملفات المرافقة لها مثل `*.db` و`*.sqlite` وملفات WAL/SHM.
- مجلدات بيانات التطبيق المحلية والبيانات التطويرية.
- النسخ الاحتياطية والصادرات والسجلات.
- ملفات البيئة الخاصة والأسرار، مع السماح بملف مثال اسمه `.env.example` عند الحاجة.

يوجد مجلد `dev-data` لبيانات تطوير اصطناعية فقط، ويحتوي على تعليمات تمنع وضع سجلات حقيقية فيه. لا تُحفظ بيانات الأطفال أو الموظفين الحقيقية في ملفات التطوير أو Git.

## 6. الشعار والهوية

نُسخت صورة الشعار المعتمدة إلى:

```text
ElMomenNursery\Resources\Branding\AlMoumenNurseryLogo.jpeg
```

تظل الصورة مرجع الهوية الحقيقي للتطبيق. لم يتم تغيير ألوان الواجهة أو بناء تصميم بصري نهائي في هذه المرحلة؛ أخذ عينات الألوان واختيار درجات متباينة ومناسبة للطباعة ما زال ضمن العمل اللاحق.

## 7. توثيق القرارات وقواعد التطوير

### `docs/decisions/0001-solution-foundation.md`

يسجل القرارات التأسيسية، ومنها اختيار Windows Forms حاليًا، وحدود المشاريع، واتجاه المراجع، واستهداف .NET 9 الحالي بعد تعديل قرار Phase 1 الأولي، وقاعدة البيانات المحلية لكل جهاز. كما يسجل المسائل التي لم تُحسم بدل افتراض إجابات لها.

### `docs/DEVELOPMENT.md`

يوضح للمطورين قواعد العمل اليومية، ومنها:

- استخدام أسماء واضحة في الكود، مع إبقاء النصوص الظاهرة للمستخدم باللغة العربية.
- وضع حالات الاستخدام في `Application` وقواعد العمل في `Domain`.
- إبقاء تفاصيل قاعدة البيانات والطباعة والتصدير والأجهزة في `Infrastructure`.
- التعامل مع الأخطاء برسائل عربية مفهومة، وعدم عرض Stack Trace للمستخدم.
- تجنب تسجيل كلمات المرور أو البيانات الحساسة في السجلات.
- فصل بيانات التطوير الاصطناعية عن البيانات الحقيقية.
- الحفاظ على التشغيل دون إنترنت، وعدم إضافة قاعدة بيانات مركزية أو صفحة تقارير أو صفحة لإدارة الفروع.

## 8. تحديث خطة التنفيذ

تم تحديث مرحلة Phase 1 في `docs/IMPLEMENTATION-ROADMAP.md` بوضع علامة إنجاز على المهام التأسيسية المنفذة، ومنها:

- تثبيت مشاريع الواجهة والطبقات الثلاث في Solution واحدة.
- مراجعة اتجاه مراجع المشاريع.
- إضافة إعدادات البناء والتنسيق والاستبعاد.
- توثيق القرارات وقواعد التطوير.
- تعريف فصل بيانات التطوير الاصطناعية عن البيانات الحقيقية.
- وضع الشعار في موارد الواجهة.

كما تم توضيح أن تثبيت SDK المطلوب ما زال شرطًا قبل البناء.

## 9. القرارات التي ما زالت مفتوحة

لم يتم اختيار أو افتراض الأمور التالية في Phase 1:

- مزود قاعدة البيانات المحلية وأداة ترحيل المخطط.
- مكتبات PDF وExcel وتقنية إنشاء Installer.
- مسار قاعدة البيانات النهائي لكل مستخدم Windows أو مسار مشترك محمي على الجهاز؛ يعتمد ذلك على طريقة تسجيل دخول الموظفين إلى Windows.
- إصدارات Windows التي ستدعمها النسخة النهائية ودقة/حجم شاشة جهاز الحضانة.
- حقول الأطفال والموظفين وقواعد الاشتراكات والمدفوعات والفواتير.
- موديلات قارئ الباركود وجهاز البصمة والطابعة وإصدارات SDK/التعريفات الخاصة بها.
- درجات الألوان النهائية التي ستُشتق من الشعار بعد فحص التباين وإمكانية الطباعة.

## 10. ما تم التحقق منه وما لم يتم

تم التحقق من ظهور المشاريع الأربعة في قائمة الـ Solution، ومن إمكانية قراءة ملفات إعداد المشاريع و`Directory.Build.props` كملفات XML سليمة.

وقت إعداد Phase 1، لم يتم تشغيل `dotnet build` أو اختبارات لأن الحل كان يستهدف .NET 10 بينما المتاح SDK 9.0.306. بناءً على طلب لاحق، أُعيد الاستهداف إلى .NET 9 ليتوافق مع Visual Studio 2022 17.14 وSDK المثبت. وبعد تغيير الاستهداف في هذه المحادثة، نجح بناء الـ Solution باستخدام SDK 9.0.306 دون أخطاء أو تحذيرات.

## خلاصة المرحلة

أصبحت حدود المشاريع واتجاه الاعتماد وقواعد التنسيق والاستبعاد موثقة ومهيأة. هذه قاعدة منظمة للانتقال إلى المرحلة التالية، لكنها لا تعني أن وظائف النظام أو قاعدة البيانات قد نُفذت. يظل التطبيق محليًا على جهاز واحد لكل فرع، وتبقى الحقول والأجهزة والخدمات التقنية غير المحسومة معلقة حتى يحددها صاحب المشروع.
