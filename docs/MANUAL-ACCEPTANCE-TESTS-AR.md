# دليل الاختبار اليدوي وقبول النظام

هذا الدليل يحوّل الخدمات والبيانات الوهمية الحالية إلى سيناريوهات عملية لاختبار النظام من واجهة التطبيق. سجّل نتيجة كل حالة بعد تنفيذها، واستخدم نسخة اختبار منفصلة من قاعدة البيانات؛ أمر `seed` يمسح بيانات قاعدة الاختبار ويعيد إنشاءها.

## 1. معلومات التشغيل والتسجيل

- قاعدة البيانات الافتراضية: `ElMomenNursery/dev-data/nursery-mockup.db`.
- لإعادة تهيئة قاعدة البيانات الوهمية من مجلد الحل: `dotnet run --project ElMomenNursery.DataSeeding -- seed`.
- يمكن تمرير مسار قاعدة اختبار منفصل بعد `seed`، مثل `dotnet run --project ElMomenNursery.DataSeeding -- seed "C:\\Temp\\nursery-qa.db"`.
- بيانات الدخول التي ينشئها المولّد: `manager` و`admin`، وكلمة مرور كليهما `Mockup@123`.
- المولّد يمسح جداول قاعدة البيانات المحددة قبل إعادة تعبئتها. لا تستخدمه على قاعدة تشغيل فعلية.
- تتغير تواريخ بيانات الحضور والاشتراكات والرواتب كلما أُعيد التوليد؛ احسب تواريخ الاختبار نسبةً إلى تاريخ التشغيل (اليوم، أمس، أول الشهر الحالي).
- القاعدة اصطناعية بالكامل. لا تُدخل بيانات أطفال حقيقية في بيئة الاختبار.

## 2. طريقة تسجيل النتيجة

لكل حالة، اكتب: **النتيجة** (ناجح/فاشل/متعذر/غير متاح)، **الفعلي**، **لقطة شاشة أو رقم السجل**، **الوقت**، **الملاحظات**. إذا كانت الحالة غير متاحة لغياب شاشة أو خدمة، سجّلها كفجوة منتج ولا تعتبرها نجاحًا.

الحكم على الكفاءة لا يقتصر على ظهور رسالة نجاح: تحقق من القيم بعد إعادة فتح السجل أو الشاشة، ومن الاتساق بين الشاشات، ومن عدم تكرار أو فقد السجلات. استخدم الأرقام المتوقعة أدناه كمعايير قبول أساسية. إذا كان هناك زمن استجابة مستهدف متفق عليه للمشروع، دوّنه في خانة الأداء قبل بدء الجولة؛ لا يوجد في مواصفات المشروع الحالية رقم أداء ملزم.
